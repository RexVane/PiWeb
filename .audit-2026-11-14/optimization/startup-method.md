# 五轮启动测量口径核对

日期：2026-11-14。以下口径先在测量前核对，测量后补充探针修复与 A/B 差异；真实结果见 [startup-comparison.md](startup-comparison.md)。

与原基线一致：

- 每轮复制新的 agent 数据后才开始计时，起点在 spawn 真实 bin/piweb.js 之前。
- health 每 100 ms 尝试，读完整响应体后，首次 HTTP 200/401 为可响应时刻；不是 TCP listen。
- 使用同一私有 IPC 令牌交换函数，cookie 仅存内存。认证 health 的累计时间包含完整响应体及 JSON 校验。
- 第一次请求 /api/sessions?limit=100，解析完整 JSON、验证 total=300 后记录自启动累计时间。第一屏返回 100 条，total 表明夹具的 300 个会话均纳入目录。
- 首页请求在 sessions 校验之后进行，读取完整响应体、UTF-8 解码和 HTML 校验后记录。它是已经经历 sessions 初始化后的 HTML 请求，不是独立冷首屏或可交互时间。
- 同规模夹具由原生成器重新生成：300 会话、299 × 20 条短消息、一个 10,000 条消息的长会话，共 25,267,221 字节；另有 10,000 普通文件、100 技能与 40 资源工作区。每轮独立复制 agent-template。UUID 和临时根目录不同，不能称字节逐一相同。
- 两次均设置 PIWEB_REMOTE_LAN=0。启动钩子在调用 ensureRemoteAccess 前返回，且 ensureRemoteAccess 自身也检查同一开关，因此不准备局域网监听或公网隧道。没有把 PI_OFFLINE 当作远程关闭开关。
- 同一环境白名单、回环监听、默认认证、默认启动预热、2 秒进程树资源采样和资源停止阈值。OS 文件缓存不清空。

有意保留的差异和新增指标：

- 基线 3 轮，本轮 5 轮。仅比较本机观测的范围、中位数，不作显著性承诺。
- 产品的默认预热顺序已经改为 sessions 完整响应后才发次要预热，整体计时仍从最初 spawn 开始，没有排除这一等待。
- 本轮记录 launcherReadyMs，使用少量 stdout/stderr 管道观察就绪行后写日志；基线直接将日志写入文件，没有这个单独时刻。就绪后后台任务仍可能运行。
- 第一份认证 HTML 的静态资源提取发生在首页计时终点之后，不计入首页请求时间。
- 原基线 helper 的 firstSessionsRequestMs 在完整响应体到达时采点，JSON 解析在其后；旧报告对这个单独字段的“包含 JSON”表述过宽。本轮保留同口径字段用于比较，并额外记录 firstSessionsValidatedRequestMs（包含解析和 total 校验）。主指标 firstSessionsMsSinceSpawn 在两次实验中均包含解析和校验。
- 新构建同时包含启动、服务端和前端优化，不能将端到端差值全部单独归因于构建校验去重。

原始基线见 [startup.json](../performance/startup.json)，最终成品绑定见 [stage-validation-verified.json](stage-validation-verified.json)。五轮、受控父阶段及完整旧新交错各两轮均在准入后执行，原始记录全部保留。

测量后的补充：

- 第一次尝试在成功一轮后，因上一轮已停止的空采样被误用于下一轮而中止。修正临时探针，令丢失判断仅接受当前 PID 的采样，轮间明确切至 pid=0；v2 五轮与随后 A/B 均使用修正后的判断。首次成功慢样本与第二轮探针错误照实保留。
- 完整 A/B 与 v2 共用计时、认证、白名单环境和采样函数；fixture 内容 hash、优化成品身份、Node 与 CPU、间隔和计时定义均逐项一致。A/B 增加旧目标、固定旧／新／旧／新顺序与四个日志里程碑观察，未更改计时点。
- 每轮仍为新进程、fresh agent 目录，复制在计时前。旧成品与新成品保留各自默认预热顺序，没有用隐藏开关改变 A/B 行为。
- A/B 前恢复并校验本轮旧临时成品会读其文件，OS cache 未清；继承的操作系统环境值没有逐轮记录，用户应用也未停止，因此不宣称机器环境完全固定。两个相邻配对只支持这次观测，无法解释或否定早一窗口的较慢五轮。
- 原始 A/B JSON 复用模板时保留了一句“基线三轮／优化五轮”，它指原先独立窗口，不是 A/B 次数。该文件实际 sequence 与 runs 明确为旧两轮、新两轮；本比较报告按四次实际记录计算。
- 测量完成后主动终止本轮进程树，Node exitCode=1 是此收尾动作的结果；每个成功样本均在收尾前通过完整响应校验。系统复核确认相关端口无监听、stage 无 Node 进程，未因 PID 后续复用而操作用户进程。
