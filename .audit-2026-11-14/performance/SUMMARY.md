## 页面加载与操作

- 首次业务导航：页面外壳约 278 ms，会话与模型等首批数据就绪约 2.08 秒。只报首屏绘制会明显低估第一次等待。
- 服务已热时：新浏览器缓存的业务就绪约 200～248 ms；热缓存约 116～155 ms，各 5 次。
- 长会话滚动已测：150 个回合、rAF 帧间隔 p95 16.8 ms，本段没有超过 50 ms 的长帧。
- 桌面和普通移动视窗各 20 次输入，可见响应计时 p95 约 33 ms；设置打开 p95 58 / 82 ms。移动长会话滚动帧间隔 p95 16.7 ms，也未见超过 50 ms 的长帧。
- 模型页面等部分操作的内容就绪上界超过 200 ms。原始定位器等待包含轮询延迟，不能把全部上界都当实际渲染耗时。追加页面内时间戳后，短/长会话各 10 次的首次目标正文就绪 p50 为 55 / 196 ms，p95 为 416 / 262 ms；下一帧 p95 为 419 / 307 ms。点击后的即时界面反馈仍约 30 ms；短会话这组包含首次慢样本，10 个样本的 p95 等于最大值。
- 较慢设备/网络模拟（4 倍 CPU 降速、100 ms 延迟、1.6 Mbps 下行）：5 次冷浏览器导航，业务数据就绪 5.44～5.58 秒，CLS 均约 0.33；已保存的 2 次热缓存导航为 2.09～2.19 秒。该整段测量主动停止，不能说已完成原定 10 导航和全部交互；单次布局归因另存。
- 首页首批 7 JS + 2 CSS 的浏览器实际传输约 299 KiB；继续观察后的 12 JS + 2 CSS 约 461 KiB。这只统计框架静态资源，不包含 HTML、接口响应或全部网络流量；构建统计中的理论 gzip 大小不是实际传输值。
- 单次布局复核确认：手机宽度下先显示桌面侧栏，约 2.20 秒时主区从 `x=280 / width=110` 跳至 `x=0 / width=390`，产生 CLS 0.33175。`AppShell` 的 `isNarrow` 初值为 false，响应式网格和侧栏样式等脚本挂载后才切换。可对照[加载中的画面](layout-mobile-slow-cold-0-cls-dcl.png)与[数据就绪后的画面](layout-mobile-slow-cold-0-cls-business.png)；截图中的未配模型状态来自合成无凭据环境。
- 合成流式压力没有取得有效验收结果：首轮超时；独立复核发现连接被替换后探针仍向旧连接投递；最后一次等待连接稳定 5 秒后重试，压力约 4.8 秒时连接仍被替换，已立即停止投递。真实快照重置了合成消息，不能将这些帧率计作有效生成压力，也不能据此宣称真实模型流式存在相同故障。三个失败记录均保留，没有继续调用真实模型。

以下均固定在同两条短/长会话之间切换，取样时回到同一短会话并强制回收，节点数量保持稳定。

因此不能用测量脚本或 Playwright 的网络记录解释该增长。堆快照中约 61.95 MB 是保留下来的合成历史正文，已追到 snapshot/state 与闭包上下文链；本轮尚未定位最终强引用位置，不把候选代码位置冒称根因。当前足以判定会话反复切换的内存稳定性不通过本轮预算，但没有外推为无限线性增长或预测数小时后的具体占用。

整组浏览器进程的私有提交量在桌面完整流程中约为 465→622 MiB；工作集合计约为 644→802 MiB，后者可能重复计入共享页。JS 堆是其中一部分，不能再相加；也不能把不同阶段的浏览器和服务端峰值相加当作同时总占用。

原生对照第一次因探针未等待工作区分组而失败，没有内存样本；修正探针后的 v2 才是有效结果。见 [原生对照数据](frontend-memory-native-v2.json)、[无页面探针对照](frontend-desktop-memory-minimal.json)、[有界堆引用分析](frontend-memory-retainers.json)。

## 后续优化顺序

1. 会话切换后旧正文的保留链：已跨三种采集方式复现，优先定位并消除多余引用，修复后用相同数据复测。
2. 手机首帧布局：让窄屏布局在脚本挂载前生效，消除先显示桌面侧栏的跳动。
3. 启动构建校验：同一次启动复用已验证的成品结果，减少共同祖先路径的重复检查，同时保留完整性及路径边界语义。
4. 工作区模型目录和会话切换尾延迟：进一步拆分初始化与重复读取成本，优化应保留各工作区独立的模型范围。

本轮没有实施上述优化。730 个冻结生产输入在测量前后完全一致，见[源码一致性检查](source-consistency-final.json)。单次生产编译及封存为 123.03 秒，这是构建成本，不是日常启动耗时；依赖来自现有安装的 junction，此次没有重做纯净安装测试。
