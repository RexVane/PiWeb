# 前端实测结果（2026-11-14）

正常桌面和移动模拟的首次绘制、输入反馈及安静长会话滚动表现良好，但本轮确认两项明显问题：**弱环境窄屏首次加载产生 0.332 布局偏移；反复切换会话持续保留历史正文，50 次后多占约 68–83 MiB，空闲 90 秒并 GC 仍不回落。** 长会话内容就绪也有超过 200 ms 预算的尾部样本。生成中体验尚未完成有效验收，不能由安静会话结果外推。

本轮只测量和分析，没有修改产品源码。成品 BUILD_ID 为 `qs_AuODvEiFduBinEf95d`，sourceHash 为 `0a8188e986da0c45600a2153ae2d4d5da4b185e18f7f23b60feb75eb83337961`。使用隔离生产服务和合成数据，不访问 live 30141、不调用真实模型、不使用用户凭据。

## 口径与覆盖

- Chromium 156.0.8078.4；桌面 1280×800，移动模拟 390×844；弱环境另加 4× CPU、100 ms 网络延迟、1.6 Mbps 下行和 750 Kbps 上行。模拟设备不是实机手机。
- 数据为 300 个会话、10,000 个工作区文件、100 个真实合成技能；长会话 JSONL 有 10,000 条消息、21,599,196 B。前端显示最近 300 条消息、150 个回合。模型接口含 43 个 provider/1,643 个目录模型，但设置面板中已配置 provider 为 0；插件为 0 package/3 内置扩展。因此不代表大型已配置模型或插件列表的渲染压力。
- 冷缓存是新浏览器 context、HTTP 缓存为空，服务及 OS 磁盘缓存已热；桌面额外保留 1 次新服务进程的首次业务导航。私密登录在导航计时前完成，不属于导航耗时。
- `shellReadyMs` 是壳与输入框出现；`businessReadyMs` 还要求首轮 sessions/models 响应完成并渲染工作区。LCP 持续采样至业务就绪后至少 1.5 秒。壳的 LCP 不能替代业务就绪。
- 下表均使用最近秩百分位，时间为 ms；n=5/10 时 p95 就是最大值，小样本不能代表线上分布。交互指标是实验室事件/DOM/帧计时，**不是用户现场 INP**。

正常本地 LCP 符合本轮 2.5 秒预算；新进程真正业务就绪为 2.08 秒。弱环境虽然 LCP 仅约 0.52 秒，业务仍需约 5.5 秒，不能把首次绘制快解释为应用已经可用。弱环境主探针保存 7 次导航后长时间无进展，经主动中止保留有效样本；其余交互/滚动/内存阶段未测，不能算通过或推断产品崩溃。

**窄屏布局偏移来源已实测确认。** 单次诊断在 2,197 ms 记录到 `.pi-main` 从 `(x=280,width=110)` 移至 `(x=0,width=390)`，输入框同步由约 116 px 扩至 390 px，这一事件贡献 CLS 0.33175355。DCL 与业务就绪截图显示：先出现桌面固定侧栏，客户端初始化后才切到窄屏布局。对应 `AppShell.tsx` 的 `isNarrow` 初值为 false，网格与侧栏 fixed/inert 依赖初始化后的值。5 个原始冷样本与独立诊断均复现。修复方向是在首次样式布局就按视口决定网格/侧栏，避免依赖 hydration 后改版；本轮未实施修复。

诊断同时记录 `/api/sessions` 从 2,159 ms 开始、耗时 1,906 ms、encoded 140,869 B；`/api/models` 从 2,161 ms 开始、耗时 3,350 ms、encoded 329,766 B。它们与首轮脚本下载/执行共同组成 5.58 秒就绪路径；这里是限速环境的完整响应耗时，不能全部归于服务端计算。

| 页面内精确补测 | n | 首次 DOM 就绪 p50 / p95 | 就绪后下一帧 p50 / p95 | 超过 200 ms 的 DOM 样本 |

## 内存：存在持续保留，需要修复

| 场景 | 起始 GC 后 JS heap | 50 次后 | 再空闲 90 秒并 GC | 同一短会话 DOM |
| --- | ---: | ---: | ---: | --- |
| 桌面主探针 | 89.34 MiB | 168.09 MiB | 未在该轮测 | 4,060 元素恒定 |
| 移动主探针 | 91.67 MiB | 174.27 MiB | 未在该轮测 | 4,061 元素恒定 |
| 无页面探针，保留 Playwright | 13.29 MiB | 91.38 MiB | **91.39 MiB** | 4,762 节点/1 文档/1,209 监听器恒定 |
| 原生 CDP，无 Playwright/Network 域 | 11.34 MiB | 79.63 MiB | **79.64 MiB** | 4,058 元素/4,528 附着节点恒定 |

无页面探针每 10 次的序列为 13.29 → 29.27 → 44.99 → 60.90 → 76.01 → 91.38 MiB。原生 CDP 对照仍增长 68.30 MiB，且 90 秒后不回落，排除了页面 PerformanceObserver、Playwright Network 缓存和短期计时器作为完整解释。这已经超过“增加 32 MiB 且持续增长”的调查线，属于实际页面/应用链路保留，不能判通过。原生对照使用脚本点击真实侧栏，仅供内存对照，不用于交互时延结论。

脱敏 heap 快照有 1,135,062 个节点/5,395,774 条边；35,051 个 fixture 历史正文字符串的 self size 合计 **61,948,784 B**。选定样本路径为 `正文 → detail 对象 → trajectory 数组 → snapshot → state → 匿名 closure/context → 多层 previous context`。这证明历史正文仍被上下文引用；本轮有界追踪未映射到最终 GC 根/具体保留函数，因此不能把 lowlight 高亮器、模型目录或某个缓存定为已证实根因。原始 snapshot 与有界 retainer 摘要已保留，可用于后续修复定位。

JS heap 不是整个浏览器内存。桌面主探针可归属 Chromium 进程的 Working Set 求和由约 644 MiB 增至 802 MiB，Private Bytes 求和由约 465 MiB 增至 622 MiB；其中包含浏览器框架开销，Working Set 还可能重复计入共享页，不与服务端 RSS 混算。

## 流式与失败边界

**3 次合成流式尝试都没有形成有效的 20 秒渲染压力验收。** 第一轮在最终 DOM 检查超时；第二轮记录 871 个 delta 后发现源早已替换、仍向关闭的旧源投递；最后一轮先确认当前会话与 OPEN 源稳定 5 秒，约 4.8 秒/192 个 delta 后源再次替换，探针立即停止继续投递。最终真实快照把合成消息重置，未满足“发送全量 message end 前已验证所有 delta 在 DOM 中”的要求。

因此这些轮次的帧/输入数字**不能作为生成中性能通过结果，也不能把合成探针失败定为真实业务流式故障**。所有失败 JSON 都保留。正常流真实模型未调用；生成中输入、滚动和长任务仍需用可控且协议一致的持续事件夹具重新验收。

完整原始数据见 `frontend-desktop-all.json`、`frontend-mobile-all.json`、`frontend-mobile-slow-all.json`；补测见 `frontend-mobile-slow-navigation-cls.json`、`frontend-desktop-session-timing-dom-ready.json`、`frontend-desktop-memory-minimal.json`、`frontend-memory-native-v2.json`、两个独立 `frontend-desktop-stream-*.json`。统计见 `frontend-metrics.json`。截图 `layout-mobile-slow-cold-0-cls-dcl.png` 与 `layout-mobile-slow-cold-0-cls-business.png` 验证布局来源。桌面 all 的整体 completed=false 仅说明尾部流式阶段失败，不抹去此前已完成的导航/交互/滚动/内存样本；普通移动完整完成，弱环境仅部分完成。
