## 审计深度要求

- 顺着调用链跨文件读：UI 组件 → hook → API 路由 → service → pi SDK 调用，至少跟到"数据真正落地/发出去"的那一层。
- 对**每个功能**给结论：`OK`（读了代码 + 有测试覆盖）/ `OK-但脆弱`（能跑但有隐患）/ `有问题`（给出 P 编号）/ `说不清`（缺信息，说明缺什么）。
- 检查防护是否**真的生效**（不是只看名字）：权限、鉴权、路径校验、并发锁、错误处理、超时、取消。
- 检查**测试是否真断言**（不是只 smoke），找出核心行为缺测试的地方。
- 关注生产可用性：崩溃面、竞态、内存/句柄泄漏、静默失败、错误被吞、Windows 平台差异、跨设备（手机）差异。

## 严重度

| 级别 | 含义 |

| **P0** | 数据丢失 / 越权（逃出沙箱或绕过鉴权）/ 崩溃 / 明确的安全漏洞 |
