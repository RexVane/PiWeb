# 可复用的项目架构图提示词

把下面这段发给 Pi，并按需要补充项目目录或关注范围：

```text
请阅读这个项目当前的源码，分析真实架构，并画出清晰的静态架构图。

先查入口、目录结构、关键模块、数据存储和外部服务，再确认它们之间的调用与数据流。图中的关系必须有已阅读的源码依据；无法确认的地方单独注明，不要把猜测画成事实。

用 Mermaid 代码块输出，让 PiWeb 直接渲染。默认用从上到下的 flowchart，按界面层、接口与业务层、运行时、存储和外部依赖分组；根据项目实际结构调整分层。节点使用简短中文，必要时附源码中的模块名。连线只保留关键关系，并用简短文字说明调用或数据含义。

视觉参考：圆角节点、浅色背景、清晰分组、细连线、充足留白。重点是层次清楚、路径易读，减少交叉和重复连线。大项目先给一张概览图，再将重要子系统拆成独立小图；不要把所有文件塞进同一张图。

最终只输出图，不加介绍、图后说明或源码清单。遵循我另行指定的图类型、语言或输出格式。
```

提示词负责让 Pi 根据源码组织准确、清晰的图；浅色配色、圆角、连线和最终展示由 PiWeb 的 Mermaid 渲染组件统一处理。需要图时再使用这段提示词，不要求普通回答都带图。
