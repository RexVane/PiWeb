# 需求

## 右侧旁聊

用户阅读主会话的长回答时，需要随时追问其中的不同内容。追问应保留当前阅读位置，并独立于主会话的上下文。

- 旁聊是右侧面板的固定入口，主会话顶栏有直达按钮；不要求选中文字。
- 打开后可以连续追问，面板可以收起、调宽或切去查看项目、提示词、Git；回来后继续使用。
- 主会话与旁聊分别滚动。发送旁聊问题、生成回答不移动主会话；打开、关闭和调宽面板保留当前阅读位置。
- 每次提问读取当前主会话的有效分支与已生成的回答作为背景，旁聊有自己的多轮历史。
- 旁聊问答不写入主 Session，不触发主会话的提问、停止、分支或压缩，也不进入主会话后续的模型上下文。
- 旁聊的 Agent 能力与主对话一致：以当前项目为工作目录，支持读取、搜索、修改文件、执行命令和构建，使用同一套技能、提示模板、插件、MCP 与模型认证。工具执行按旁聊用户的请求进行，不把主对话引用自动当成待办。
- 页面保持现有简洁样式，只保留问答、输入框、模型选择、上下文环和历史入口；完整 Agent 能力在底层提供，不增加工具菜单、附件区或过程面板。插件确实需要确认或输入时才显示相应对话框。
- 旁聊默认使用主会话的模型与认证，通过独立工具循环查询项目并回答；只执行用户在旁聊提出的问题，不把引用的主会话任务自动当成待办。
- 旁聊可以单独选择模型：默认跟随主会话当前模型；选定后只影响之后的问题，选择随这份旁聊一起保存。模型不可用时明确提示。
- 按主会话分别保存旁聊记录与草稿，存储在当前浏览器；关闭、切换主会话、刷新后恢复。不同设备之间不同步。
- 「新旁聊」建立独立上下文，已有旁聊记录保留并可再次查看、继续提问。
- 支持停止当前旁聊回答、错误后重试；停止与重试只作用于该旁聊。
- 面板保持简洁：标题、新旁聊与历史入口、问答内容、输入框、发送/停止。没有输入框下方的轮数、耗时、token、缓存命中等统计。
- 实际发生背景截断、输出到达上限、连接失败或浏览器保存失败时，在旁聊内给出简短提示。
- 手机使用现有右侧抽屉，输入框保持在可见范围内。

验收重点：连续旁聊后主会话文件、有效分支和消息保持原样；真实浏览器中发送、打开、关闭和调宽旁聊保留阅读位置。
