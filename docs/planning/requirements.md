# 需求与已确认的产品行为

维护日期：2026-11-15。本文记录已确认的产品约束，不以历史版本的“当前没有待实现需求”代替后续任务清单。实现与验证状态见[进度](../state/progress.md)，技术边界见[技术方案](technical-design.md)。

## 当前约束

- **本机登录与远程连接**：所有启动方式默认认证。本机由 `piweb` 启动器打开登录页；再次启动可进入已有实例，不在终端输出登录凭据。远程自动准备，不要求先打开连接开关；设置中的同一个动态二维码用于同一 WiFi 和外网。该码使用可达的公网 HTTPS 地址，不承诺断网时也能扫码。局域网直连 HTTP 保留，不能在说明中写成已加密。
- **资源入口与作用域（2026-11-15 按当前实现修订）**：侧栏当前只有扩展（Extensions）与自动化任务两个工作区视图；技能、提示词的工作区视图在代码中存在但界面没有入口，资源市场已移除（组件、路由与文档承诺同步删除）。模型配置仍在设置中。扩展视图按所选工作区展示个人/项目作用域与本地/包来源；不把“技能/提示词/市场有侧栏入口”作为当前承诺。包附带技能不能按独立技能删除整个包；卸载包必须是扩展页的明确操作。
- **安装与数据保留**：npm 插件安装、更新、卸载先在独立目录准备，再提交安装与设置；准备失败保留原状态，中断提交可恢复，旧代保留恢复索引。会话与可删除本地资源采用可恢复移除，不把取消归档等同于从备份自动恢复。用户的数据和未提交改动不因整理任务被重置。
- **提示词与技能（实现约束；当前 Web UI 无独立入口，2026-11-15 按实现修订）**：提示词与技能仍由 pi 的共享资源机制加载并提供给引擎/API；资源变化在读取/会话执行边界重新检测，忙碌会话推迟应用并提示。任务要求展示实际工作区和当前会话分支的提示词来源，这属于资源层语义，不代表当前侧栏有提示词入口。技能空正文与文件引用、BOM 和嵌套 YAML 需要保持有效，开关只改对应字段。不能以模型目录读取或会话创建触发 `!command` 认证命令；明确的请求认证仍支持用户配置的命令。
- **权限档位**：仅可查看、工作区内修改、完全权限三个语义保持稳定。受限命令不可用时不自动提升；Windows 文件编辑有独立的目录保护，不因 pnpm 依赖中的硬链接而扫描/拒绝整棵工作区。命令执行对共享硬链接可写根的限制仍保留。一次批准只用于被展示的具体调用，包括 codemode 和扩展嵌套调用。细节见[权限档位与工作区边界](../workspace-isolation.md)。
- **自动化任务**：支持间隔、每日、每周和 cron，显式保存工作区、模型与权限档位；服务运行期间调度，每次产生独立会话，最多并发四项。无人值守不自动批准交互请求；停机漏跑按宽限规则记为跳过，排队不误记为离线。损坏记录通过预览/备份/显式恢复处理，不无声跳过权限或运行记录。
- **验证**：源码测试、真实安装包、浏览器和公网连接是不同证据。报告写清日期、源码版本、跳过与平台，不用测试通过推导所有平台或所有第三方服务均无问题。

## 延续的界面决策（2026-10-17）

以下是用户明确表态过的界面决策，继续按其意图维护。

- **技能怎么显示**：`/skill:name 正文` 在 pi 侧会展开成一条用户消息（SKILL.md 正文 + 正文接在 `</skill>` 之后）。界面**不**把它渲染成用户气泡，而是在本轮过程步骤里显示一行「使用技能 X」，用户打的正文挂同一行、可展开看全文。依据：Claude Code 把技能做成 `Skill(skill, args)` 工具调用（args 是入参，tool_result 只有 `Launching skill: name`），Codex 则没有技能步骤、只是读 `SKILL.md` 文件。
- **模型名不进对话区**：消息下面那一行不再显示模型名（原先出现在模型错误步骤行尾）。输入框右下角的模型按钮保留（切换模型要用）。
- **增长树**：不出现横向滚动条（滚动容器锁 `overflow-x`；行悬停的 `translateX(2px)` 会被裁在容器内）。
- **新会话页**：进入时用 pi 设置里的建议模型兜底，不再每次都要求先手动选模型；用户在工作区里显式选过的模型优先。
- **正文里的文件路径**：点开用**页内文件查看器**（不离开页面，路径不存在时查看器自己报「文件不存在」），不是本机编辑器；工具行上那个「在编辑器中打开」按钮仍然是本机编辑器。
