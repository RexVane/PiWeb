# PiWeb 权限控制审查

审查日期：2026-11-13，验证截至北京时间 15:03。项目版本 0.3.30，Pi SDK 1.5.2。针对当前工作目录中的代码；本轮未修改生产代码。

## 结论

三档权限、会话独立保存、工具调用检查、登录认证和自动化运行前应用权限均已具备，适合继续沿用。但「工作区内修改」存在可复现的越界写入和运行中降权漏拦，目前还不能作为可靠限制模型写入范围的基本保障。

修复下面四项并补上回归验证后，这套结构基本能够满足单用户日常使用。它限制模型经过工具管道发起的操作，不是操作系统隔离，也不是多人角色权限系统。

## 实际能力

| 档位 | 模型的常规工具能力 | 当前边界 |
|---|---|---|
| 仅可查看 | read、grep、find、ls、询问用户 | 常规写入和命令被拦；读取不限制在工作区内 |
| 工作区内修改（默认） | 读取、write/edit、可选 codemode/工具发现 | 无 shell；MCP 依赖服务器声明只读；文件路径限制存在下述漏洞 |
| 完全权限 | 全部已加载且可用的工具 | 不限制文件路径和命令 |

权限按会话保存。项目扩展的信任设置是另一层控制；已获信任的扩展自身与 PiWeb 具有相同进程和系统权限。用户直接输入的 `!` 命令不受模型工具档位限制，这在现有设计文档中已有说明。成功登录的设备都获得主人身份，没有访客或协作者角色划分。

自动化会在提交提示词前应用任务自己的权限档位；应用失败即停止。普通会话的工作区档会拦截 `manage_automation`，避免借任务设置绕开当前档位。

## 已确认问题

### P1：文件 URL 绕过工作区写入边界

位置：[permission-gate.ts:42](D:/AIApp/PiWeb/src/lib/permission-gate.ts:42)，调用处第 95 行。

权限检查的 `resolveModelPath` 用 `path.resolve(cwd, raw)` 处理 `file:///D:/...`，把它判定成工作区内的一个字面路径；Pi SDK 的 `resolveToCwd` 会把相同参数按文件 URL 转换为实际绝对路径。校验的目标与写入的目标不同。

复现：隔离会话设为 workspace，通过真实 SDK 的模型工具调用发送指向工作区外临时文件的 `file://` 路径。检查结果 `inside: true`，工具结果 `isError: false`，外部文件实际创建成功。全程未替换权限处理器或文件工具。

修复要求：校验和执行必须采用一致的路径解析语义；支持的文件 URL、平台路径、Unicode 空格和 `@` 等别名都必须检查最终实际目标，或一致拒绝不支持的写入路径形式。

### P1：运行中降到工作区档后，已准备的调用仍可越界执行

位置：[agent-manager.ts:1698](D:/AIApp/PiWeb/src/lib/agent-manager.ts:1698)，尤其第 1705–1709 行。

`tool_call` 准备阶段检查路径和 MCP 只读声明；真正执行时的 `guardToolExecution` 只再次检查工具名称。write 和 MCP 工具名在 workspace 仍可能被允许，所以准备阶段曾被 full 放行的调用会保留旧权限。

复现：真实 SDK 并行批次先准备一个外部 write 和一个未声明只读的 MCP 操作，在最后一个 read 的事件处理器处暂缓；确认两份目标文件均不存在后，将会话从 full 切到 workspace，再释放批次。两个操作均成功，外部文件均创建。原权限处理器保持完整。

修复要求：实际调用入口必须依据最新档位重新执行完整检查，包括路径和 MCP 只读声明；检查过程中发生权限变化也应避免使用过期裁决。已经执行完成的动作无法靠切换档位撤回。

### P1：配对码兑换没有防猜测限制

位置：[pairing.ts:67](D:/AIApp/PiWeb/src/lib/remote/pairing.ts:67)，公开入口 [pair/route.ts:16](D:/AIApp/PiWeb/src/app/pair/route.ts:16)。

六位码仅有发码限流，没有兑换失败次数、冷却时间或兑换速率限制。开启远程入口且存在有效配对码时，未登录请求可以持续猜测；成功即可获得主人身份 Cookie。120 秒有效期和一次性消费缩小了时间窗口，但不替代兑换限制。发码目前还使用 `Math.random()`。

复现：只在隔离进程内调用真实路由函数，使用独立测试密钥；连续 1,000 个不同错误码全部返回错误码跳转，无一次限流。随后有效码仍签发 Cookie，该 Cookie 被认证网关接受访问受保护 API。没有访问实际运行的服务，没有使用用户的真实配对码或凭据。

修复要求：为兑换增加失败上限和冷却/速率控制，避免仅依赖可伪造来源信息；改用密码学随机数生成短码。保留有效期、一次性消费和原有发码限制。

### P2：真实路径检查遇到异常时默认放行

位置：[permission-gate.ts:68](D:/AIApp/PiWeb/src/lib/permission-gate.ts:68)。

`realpathLoose` 遇到非 ENOENT/ENOTDIR 的错误时返回原字面路径，可能把无法核实的外部链接目标判为内部。缺失文件可以向上找已存在祖先，但权限错误或 I/O 错误不能视为路径安全。

验证方式：隔离目录中建立指向外部临时目录的 junction；正常检查会拒绝。仅对目标 `realpath` 注入 EPERM 后，相同权限请求返回放行。这一项是故障注入验证，未声称已在真实 ACL 错误条件下成功越界写入。

修复要求：无法核实路径时拒绝操作并返回清晰错误；保留不存在的新文件通过最近已有祖先校验的正常行为。
