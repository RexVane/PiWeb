# 权限档位与工作区边界

维护日期：2026-11-14。适用于当前源码；历史审查与本轮验证日期见[进度](state/progress.md)。

PiWeb 在 Windows 上把文件工具和命令分开保护。文件工具固定真实目录的句柄后原子替换文件，不创建子进程、不遍历整棵工作区，也不修改 ACL。命令使用 LPAC AppContainer：每个实例有独立 SID，只给该 SID 授予明确允许目录的访问权限，不修改目录原有的完整性标签。

## 权限档位

| id | 界面文案 | 文件工具 | 命令执行 | 写入范围 |
|---|---|---|---|---|
| `readonly` | 仅可查看 | 只读工具 | 只读沙箱 | 子进程不能写入工作区或临时目录 |
| `workspace` | 工作区内修改 | 工作区文件读写 | 可写沙箱 | 会话工作区、明确配置的额外目录和私有临时目录 |
| `full` | 完全权限 | 全部 | pi 的本地执行方式 | 当前用户权限允许的范围 |

旧的 `standard` 值由 `normalizeToolPreset` 转换为 `workspace`。命令隔离能力不可用时，受限档仍可使用有独立目录保护的文件工具；原生目录保护也不可用时拒绝写入，不自动改成完全权限。

## 三层检查

1. 工具白名单决定模型能调用的工具。
2. 执行期闸门验证当前档位、路径、工具参数以及嵌套调用。工作区路径采用与 SDK 一致的路径语义，检查真实文件位置。没有可判定名称或参数的调用不获得默许。
3. Windows 文件写入从盘符根开始逐层打开真实目录，拒绝重解析点，保持禁止写/删除共享的句柄直到同目录原子替换完成。命令通过受限子进程执行，文件访问由 Windows 检查。Linux 使用目录文件描述符；macOS 等平台目前只有路径检查与原子替换，不能声称具有同样的内核边界。

工作目录本身不是隔离边界；路径闸门也不能替代子进程权限检查。

## Windows 后端

代码位于 [windows-acl.ts](../src/lib/sandbox/windows-acl.ts)、[manager.ts](../src/lib/sandbox/manager.ts) 和 [bash-operations.ts](../src/lib/sandbox/bash-operations.ts)。

- 命令能力探测实际创建隔离实例并启动其中的 Node。当前只支持 Windows x64；仅加载到原生库不算探测成功。它不决定文件工具是否可用。
- 每次建实例创建唯一 AppContainer SID 与独立临时目录。工作区模式给予允许目录 Modify；只读模式给予工作区读取权限，临时目录也不可由子进程写入。
- LPAC 不使用宽泛的 `ALL_APPLICATION_PACKAGES` 授权。允许读取系统运行所需资源，并启用网络相关能力。
- 命令实例授权前检查物理目录，拒绝根目录链接及已有硬链接文件；使用流式目录枚举、最多 32 个并行文件检查，不跟随 junction。根目录持有带 `FILE_LIST_DIRECTORY` 且禁止移除共享的句柄，避免授权期间替换它。文件工具只检查正在写入的路径，因此 pnpm 依赖中的硬链接不影响普通源文件编辑。
- DACL 更新使用跨进程互斥锁；只增加或撤销当前沙箱 SID 的授权，保留原完整性标签、其他用户与其他活动沙箱的权限。
- 固定 Node 运行时复制到私有目录，用于能力探测与内部受限操作；运行时清空宿主注入的 `NODE_OPTIONS` / `NODE_PATH`，避免不同启动器的预加载干扰。文件工具不依赖该 Node 副本。准备私有目录是 PiWeb 自身的写入；只读承诺针对工具操作。
- 标准输出和错误使用匿名管道，不在工作区写日志文件；只允许标准输入输出句柄继承。每条命令输出最多 8 MiB。
- 进程先暂停创建，再加入禁止脱离的 Job Object，最后启动。超时、取消、沙箱释放、命令退出或宿主退出会终止该命令的整个后代进程树。
- 受限子进程过滤 API 密钥、访问密钥、令牌、secret、password、credential 及 PiWeb 登录/构建锁变量；显式环境覆盖也不能重新带入。PATH、代理与普通 shell 配置保留。需要宿主凭据的本地 CLI 依完全权限档的既有执行方式运行。
- 正常释放等待活动命令结束，撤销自身 SID 的授权并清理私有实例。沙箱缓存包含会话、物理工作区、模式、额外目录和解释器配置，旧实例释放不会删除新实例的临时目录。

### 额外可写目录

配置位于 `~/.pi/agent/web-sandbox.json`，也可通过 `GET/PUT /api/sandbox` 读取或更新：

```json
{ "version": 1, "additionalWritableRoots": ["D:\\AIApp\\shared"] }
```

只接受存在的物理绝对目录，不接受文件、相对路径或 junction 根，最多 8 个。写配置采用跨进程锁与原子替换。读到无效条目会跳过；这些条目不会扩大实际授权。工作区模式每次执行读取配置，配置变化产生新的实例；只读模式不使用额外可写目录。

### 解释器兼容性

受限档使用 `cmd.exe`。WSL 的文件访问不受本后端约束，不能作为受限解释器。原生 Git Bash/MSYS 需要沙箱外的共享系统对象，当前 LPAC 后端无法安全提供，因此也回落到 `cmd.exe`，同时给出原因。

这意味着 Bash 专用语法在受限档不能照搬。安装在用户目录中的 Node、Git、npm 等工具，也可能因缺少读取或执行权限而失败。内部 Node 副本可用不代表任意安装位置的命令都能执行；即使它不能启动，文件工具仍使用独立的原生目录保护。PiWeb 不为兼容工具自动扩大授权。`full` 档保留 pi 的本地解释器配置。

### 一次授权

模型须先尝试具体操作，在被拒后通过 `request_permission` 请求 `workspace` 或 `full` 范围。审批卡展示完整工具名称和参数，批准只绑定对应的一次调用；不同路径、内容或参数不能借用这次批准。拒绝、超时、切换上下文或重启不会留下可重复使用的授权。

write/edit/bash 的授权在会话本地的工具定义中同步取走，直接调用、codemode 和扩展嵌套调用共用同一入口。SDK 改写工具描述产生的声明副本也保留这一入口。Bash 的审批上下文使用该定义构造时实际捕获的命令前缀。

审批决定与授权使用记录写入会话 JSONL 的 `piweb_permission` 自定义条目，随会话导出，且不作为模型消息上下文。

## 实际边界与限制

| 通道 | 行为 |
|---|---|
| 宿主提供的只读文件工具 | 保留原有读取范围；不把文件写入授权误当成读取授权 |
| 受限命令读取 | 可读明确授权的目录与必要系统资源；不能据此承诺读取任意用户目录 |
| 网络 | 网络能力启用；此后端不是断网模式，也不是域名过滤器 |
| 既有硬链接 | 命令的可写目录有共享硬链接时拒绝建实例，避免给目录外别名授权；文件工具只拒绝直接写入硬链接目标，其余源文件可编辑 |
| 扩展自身代码 | 扩展仍在宿主进程执行；安装和信任扩展仍是独立的权限决定 |
| Windows 非 x64 或不支持所需安全操作的文件系统 | 原生后端不可用，对应受限操作拒绝执行；Linux 文件工具使用 dirfd，其他平台路径保护限制见上文 |
| 已批准的完全权限操作 | 解除该次受限执行，按当前用户权限运行 |

本后端不代表完整虚拟机隔离。UAC 提示、宿主扩展发起的界面操作，以及用户主动批准的提权仍需分别看待。没有对安全桌面进行自动点击或提权链路的实际验收；禁用 UAC 的环境不属于已验证的安全配置。

## 排障

`sandbox unavailable` 表示命令实例或实际运行能力无法建立。常见原因包括原生依赖未安装、不是 Windows x64、目录授权失败、根目录存在链接或硬链接、运行时无法启动。普通文件编辑不再触发这类整树授权或 Node 启动。pnpm 项目需要任意 shell 写入时，共享硬链接风险仍存在，应使用不共享硬链接的工作区或明确批准那条命令。原生文件保护报不可用时可补装可选依赖 `koffi`；目录占用错误应关闭正在移动该目录的程序后重试。

旧版本曾给工作区设置全局 Low 完整性标签。新版本不再这样做，也不会擅自把旧标签改成 Medium；原始标签未被记录时，不能推断它应该是什么。强杀后可能留下旧版本标签或实例 SID 授权，不能用统一覆盖完整性标签的命令当成通用恢复方案。正常释放只撤销当前实例的 SID 授权。
